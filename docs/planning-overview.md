## Planning documentation

These documents capture the design rationale, constraints, and implementation notes behind Daps features that are still in progress or haven't been reviewed for graduation yet.

A planning doc typically covers the why behind a design decision, the trade-offs considered, and the specific implementation approach chosen. They're written primarily as a guide during development — part work-item spec, part implementation notes.

Once a feature is stable and the doc has been reviewed, it graduates to a section like [Workflows](/workflow/workflow-overview/) or Configuration with the implementation scaffolding trimmed back to what's useful as reference documentation.
